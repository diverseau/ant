# ChatGPT Dots — Channels & Integrations

## Channels (how you talk to a dot) [OFFICIAL learn.chatgpt.com/docs/dots/channels; help.openai.com 20001530; learn.chatgpt.com/docs/enterprise/dots-admin-guide]
| Channel | Status at launch | Details |
|---|---|---|
| ChatGPT desktop / web / mobile app | Live | message in the dot's conversation; mobile for messaging after desktop setup ("when the supporting update is available") |
| **Voice calls** in ChatGPT | Live | phone button in the conversation, or **Call** in profile (desktop app); can type while on call; ending call ends voice conversation, assigned work continues; **dot cannot call you** ("calls initiated by your dot are planned for after launch") |
| **Slack** | Live (admin must allow) | Connect from dot profile → **Add** (desktop). DM the dot, or add it to a channel and mention it in a thread (handle e.g. `@tibo-alfred`). By default responds **only to you**; you can instruct it to engage others (it may DM you first to ask what you're comfortable sharing). **Only the owner can direct their dot** via Slack DM/mention; others' messages don't start work, but their messages can be used as context in a thread you bring it into. Adding it to a channel does **not** start monitoring: tell it which channels/events to watch and when to notify, and ask it to confirm the recurring task. Anyone with conversation access sees its posts |
| **Microsoft Teams** | **Invite-only alpha** per the admin guide ("Microsoft Teams access is limited to an invite-only alpha"); learn.chatgpt.com/launch post say "message your dot in Slack and Teams" | same model as Slack. (Earlier version of these docs said "Live"; corrected.) |
| **Texting (SMS)** | learn.chatgpt.com: "Texting is coming soon." Help center: **limited beta**, Pro users in the **US** only, not Business/Enterprise, may not reach every Pro user; third-party provider; connect phone from desktop app; reply **STOP** to stop; message/data rates may apply | guide warns to avoid sensitive info in texts |
| Email | **No standalone email address** at launch; can use your connected personal email account via plugin | leaked strings suggested an email channel [UNVERIFIED] |
| Other messaging apps / phone-initiated calls | "planned" / after launch | |

Behavior rules:
- **Same dot, same memory across channels**; switching doesn't reset. Slack/Teams conversations show only messages exchanged there (not mirrored from ChatGPT). Dot checks that you've allowed sharing before it discloses private-conversation info to others; context can inform work, but not disclosure to a new audience.
- **Routing**: tell it which updates go where (routine progress in ChatGPT, decisions to Slack) and what warrants interrupting you (e.g. deadline at risk).
- Channel connection is independent from app and computer permissions (adding Slack ≠ inbox access ≠ computer access).
- Setup of messaging channels is from desktop.
- **Slack admin chain** [OFFICIAL admin guide]: ChatGPT workspace owner enables *Use dots* + *Add dots to Slack*; Slack workspace owner/app manager ensures the ChatGPT app is installed/approved; each member connects their dot to Slack from the profile. Enabling the permission does not install the app or connect a dot.
- **Not the same as `@ChatGPT` in Slack/Teams**: that is a separate Business/Enterprise product (mention `@ChatGPT` in a channel/thread/DM; shared company connections; Codex Cloud delegation; Slack Connect channels unsupported). The dots Slack connection is separate. [OFFICIAL learn.chatgpt.com/docs/third-party/slack; enterprise/chatgpt-slack-and-teams]

## Apps / plugins [OFFICIAL]
- "Connect to over **4,000 apps** through OpenAI's plugin ecosystem." [OFFICIAL launch post] Not itemised in dot docs.
- One **universal plugin directory** shared by Chat, Work, Codex. A plugin can bundle **skills, MCP servers (apps), browser extensions, hooks** (hooks not in cloud-orchestrated Work). Installing a plugin doesn't authorize its apps; connect separately. **Sign in with ChatGPT** beta for partners (Airtable, GitLab, HubSpot, Notion, Supabase, Vercel). Plugin permissions are **shared across dots, ChatGPT, ChatGPT Work and Codex**; set read-vs-send per plugin (e.g. allow read email but not send). [OFFICIAL help.openai.com 20001529; learn.chatgpt.com/docs/plugins]
- Docs examples for dots: Gmail (find email), Google Drive (documents), GitHub (investigate issue, prepare PR). Commonly cited others (Google Calendar, Outlook, SharePoint, Dropbox, Slack, Notion, Linear, Canva, Figma, HubSpot, Atlassian Rovo, Adobe Acrobat, Shopify) [SECONDARY]. Apple Messages plugin exists for macOS desktop Codex/Work (not documented for dots).
- Developers can build plugins/MCP servers and (DevDay) "plugin extensions" (sidebar, interactive panels, file viewers) and **MCP Events** (proposed spec) so plugins can start automations; Sites can host plugins. [OFFICIAL DevDay recap]
- Admin side: Plugin controls (app availability, role access, allowed actions); dots follow existing ChatGPT app connections; "Use password manager" workspace capability.
- **Website sign-in**: same private flow as ChatGPT Work: dot sends a sign-in request → private form (credentials go to the remote browser outside the conversation, not the model) → or **Take over** to sign in yourself → **Done**; **Save to Passwords** optional; using a saved login for a new sign-in needs your confirmation; sessions persist until sign-out/expiry; cloud browser has its own sessions, separate from your laptop's; some sites block cloud browsers → ask it to try your connected computer (creates a separate local task; doesn't transfer session). Dot context does not retain credentials, images or screenshots.
- **Purchases**: can buy with a card saved on a merchant website; requires your approval (may be given in advance if it covers that purchase).
- **Codex integration**: dot can create **cloud tasks in Codex** (needs a Codex environment you created first) and, with your computer connected, **Work or Codex tasks on the local machine**, continue existing local Codex tasks, use **local skills**, and fall back to the local browser when the cloud browser is blocked. Codex/Work tasks started by the dot count toward those products' limits. Local access requires computer online + ChatGPT desktop open; separate from Codex connection / Work Sync. Camera/mic/screen access needs connected computer **and** OS-level permission for the ChatGPT app.
- **Event-triggered automations**: dot docs: "when a connected service supports event monitoring… ask it to confirm which events it can follow"; connecting Slack/another source alone doesn't create a monitoring task; example "when a new bug report appears in a Slack channel". ChatGPT-wide: scheduled tasks and event triggers (e.g. new email/Slack message) on web/mobile for eligible plans; Team Tasks for Business/Enterprise. [OFFICIAL]
- **Agents API / Codex harness**: DevDay announced the **Agents API with computer use** (multi-agent, tool search, compaction; OpenAI runs infrastructure; available through API and in Codex/Work on Pro 500 and Enterprise), Bedrock Managed Agents powered by OpenAI. A dev.to post shows a `client.agents.sessions.create({agent_id:"dot-eng-primary", run_in_background:true})` snippet labelled "conceptual" — **[UNVERIFIED]; no public *Dots* API announced** (docs for Agents API sessions exist at learn.chatgpt.com sidebar but are not Dots).
- GPT-6 Astra model is available via OpenAI API, Microsoft Foundry (`gpt-6-astra`), OpenRouter (`openai/gpt-6-astra`), AWS Bedrock (`global.openai.gpt-6-astra`), GitHub Copilot tiers. [SECONDARY, not re-verified]; GPT-6.1 Sol (DevDay) is the cheaper sibling (1/5 price) [OFFICIAL]. Enterprise model controls **do not apply to dots**.

## Not supported / gaps
- No Discord, Telegram, WhatsApp, iMessage native channel.
- No public Dots API documented.
- Dot can't initiate calls; no own email address; one personal computer connection at a time; no mobile creation; Teams invite-only alpha; individual memories can't be viewed/edited/deleted.
- Not available: under-18s; EEA/Switzerland/UK for Pro; FedRAMP workspaces, EKM workspaces, inference residency AE; **no data/inference residency during Enterprise beta**; if any cloud policy has `enforce_residency`, local computer access for dots is unavailable. [OFFICIAL cloud-local-access, dots-admin-guide]
