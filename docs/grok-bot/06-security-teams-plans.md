# Grok Bot — Safety, Teams/Enterprise, Plans & Limits

## Approvals & Auto Review [OFFICIAL]
- **Auto Review** = independent review model evaluating risky actions: shell commands, plugin calls, computer use, automation writes, delegation. Outcomes: **permit / require approval / block**. Does NOT review every side effect (memory writes, most settings changes are exempt).
- Approval card ("Review an action") shows proposed operation: **Allow once · Always allow (saves a matching rule under Auto-review Rules) · Deny**.
- Rules: one short rule per action; two kinds, **Ask first** (always stops) and **Allow automatically** (proceeds only if the reviewer finds no other reason to stop); personal rules can only *tighten*; **"Ask first" wins** on conflict. Team rules cannot be disabled by members. Enterprise can enforce Auto-review org-wide ("Required by your admin"); a group can lift the lock ("Don't enforce for this group"). Auto Review is model-based, off-by-member-choice unless enforced; **Team Bots in teammates'/Slack/group chats run *without* Auto-review unless Enforce is on** (nobody there can answer an approval). Examples from docs: "ask first before sending any external email"; "allow automatically when running git status in /workspace/reports"; avoid "allow everything in the browser".
- Where approvals surface: in chat, sidebar attention state, push notification.
- Bots **act as the signed-in member**; no independent identity; never more access than the member.
- Connector tokens never given to the model. Passwords/2FA are human handoffs. Secrets are masked and write-only.
- Local execution policy: per-command approval default (card shows the exact command). Member choices: Ask every time (default) / Always allow / Never. First-use dialog: "Allow Grok Bot and all Bots to run commands on your local computer?" with Always allow / Allow once / Never / Deny once (Esc). Local execution also covers reading and moving files between cloud and local machine. Separate from Auto Review. [OFFICIAL cursor.com/docs/grok-bot/security]
- Prompt injection: outside content marked untrusted to the model; Auto Review + network policy + approvals + per-user isolation; "reduce, but don't eliminate" risk. No built-in DLP hooks; no customer EDR feed.

## Isolation
- Cursor-hosted only (no on-prem, no BYO image). Per-user **Firecracker microVM** (hardware-isolated). Bots of one user share the VM; "isolates personalities and workspaces, not compute."
- Hibernates when idle; durable disk; daily encrypted control-plane backups; optional auto-terminate of 30-day-unused computers (Enterprise, off by default; durable disk kept, member's next message starts a fresh computer).
- Computers run in the **US today**; Cursor's separate US-only data-residency program does **not** apply to Grok Bot by default; written residency commitments via account team. [OFFICIAL security FAQ] (Earlier line "US-only residency on request" corrected.)
- Model allowlist: Enterprise-only and enforcement "not guaranteed" (onboarding acknowledgement). Zero Data Retention follows Cursor's provider agreements; no separate ZDR control.
- Privacy Mode required (Legacy Privacy Mode blocks Grok Bot). Zero data retention at model providers under Privacy Mode.
- Certs: ISO/IEC 27001 and 42001 (issued by Schellman; Grok Bot in current scope); trust.cursor.com. Anysphere/Cursor is the certified entity.
- Not supported: on-prem, in-perimeter, bring-your-own-image; per-org retention policy; customer-managed point-in-time restore of a computer. Deletion per DPA within 30 days of written direction after service ends; account deletion removes agents/chats/computers/plugins within 30 days.

## Team / Enterprise controls
- **Teams plan (self-serve)**: on by default for every member, no switch, no Premium seat; stays off for Privacy Mode (Legacy) or legacy request-based plans. **Enterprise**: admin enables (waitlist at launch), group-based "Manage Group Access", SCIM 2.0 (Okta/Entra), SAML SSO (Okta, Entra, Google Workspace, OneLogin). "Invite Team" button on the dashboard Grok Bot page (email/invite link).
- Admin dashboard (cursor.com/dashboard → Grok Bot page; admins only). **Teams + Enterprise:** Cloud Agents delegation toggle (default on), public template sharing (Enterprise starts off, others on), Manage Team Bots (All team / groups / None; members can't hide), connector policy via Team Marketplace (no separate list; can't push connectors), Execution on Local Computer ceiling (Always allow [default; member decides] / Ask every time / Never allow), Team Rules (scope Cursor / Grok Bot / both; always required). **Enterprise only:** org-wide enable switch + Manage Group Access, SCIM, MCP allowlist, Allow Local Egress (default on), Enforce Auto-review (default off), team Auto-review rules, Network Controls (No policy=allow-all / Allow all / Defaults+team allowlist / Team allowlist only; domains + IP ranges with ports; no entry cap; directory-group policies + lock; running computers apply in ≈1 min, sleeping ones on wake), Team Setup (install-script manifests; run on every computer; refresh ≈ daily), **Team Secrets** (env vars for Team Setup scripts only — not for Bots; ≤100, ≤32 KB each, ≤96 KB total; reserved names PATH/HOME/SAND_*/LD_* rejected; dashboard only, not in Admin API), Grok Bot Computers (Recreate / Terminate / Delete VMs and Data, bulk, one operation per team; org admins only), **Terminate Inactive Computers** (30 days idle; **off by default**), **Action Recording** (off by default; sanitized metadata incl. tool calls, decisions, shell commands (scrubbed), browser navigations (scheme://host/path), computer-use counts without screenshots; 90-day retention; invisible on Audit Log page), audit logs (control-plane events incl. Bot creation, access changes, Team Setup, MCP auth, Slack links, routines; SIEM stream), OpenTelemetry export (`cursor.surface=grok_bot`), **Conversation Insights** (Analytics → Grok Bot source: Type of Work / Level of Automation). No separate Grok Bot spend cap. [OFFICIAL cursor.com/docs/grok-bot/teams, /security, /computers]
- Self-serve Teams do **not** see Network Controls, Team Setup, Team Secrets, Action Recording, Enforce Auto-review, audit logs etc. (earlier version of this file listed them without plan labels).
- Group settings can only *widen* team baselines.
- **Team Bots** [OFFICIAL cursor.com/help/grok-bot/team-bots; docs.x.ai/grok-bot/team-bots]: owner creates (New → Create new Team Bot; or Share → Publish to Team from an existing Bot, choosing what to bring: plugins, secrets, memories, skills, files, routines; "Copy Bot / Start fresh"); setup pane = Plugins, Secrets, Skills, Files; needs a real name + description before teammates can see it; Publish to team → teammates find under New → Team Bots (search ≥3 chars) or via Copy link; each member's chat is private (owner can't read); team memory (saved only when someone says the team should have it) + private per-person notes; Bot uses owner's plugins/secrets, plus the member's own connectors **after asking** (card: Allow once / Always allow for this Bot / for all Team Bots / Skip; reset at Settings → General → Team Bots → Clear connector preferences); chats consume the *member's* usage; usually runs on the member's computer (separate computer if member's privacy mode is stricter than owner's); in Slack/threads/groups uses its own shared computer. Team Bot secrets: ≤25, value 8–4096 bytes, uppercase env-var names, redacted as [REDACTED] in outputs. Files: .txt/.md/.markdown/.csv/.json/.yaml/.yml ≤256,000 chars each. Approval cards only in owner's own chat. No voice chat with Team Bots. Create/publish/edit/Slack-connect on desktop only. Unpublish hides it (chats/routines return on republish); delete is irreversible for the team.
- Rollout prerequisites: allowlist `*.cursor.sh`, `*.cursor-cdn.com`, `*.cursorapi.com`, `*.cursorvm.com` and nested `*.*.cursorvm.com`, exempt from TLS inspection on every profile incl. off-network; move off Privacy Mode (Legacy); plan for shared egress IPs. Desktop-app deployment: Jamf/Kandji/Intune (.dmg), Intune/SCCM (Setup .exe `/S`, user context), Ansible/Puppet/Chef (.deb/.rpm); no MSI/PKG; no setting disables auto-update on mac/Windows/AppImage; builds expire ("Update required" once below minimum version or >~14 days old with newer release); hosted computer image can't be pinned and isn't MDM-enrolled. [OFFICIAL cursor.com/docs/grok-bot/deployment]
- Admin API covers enable, capabilities, Enforce Auto-review, group access, network policy, team rules, setup scripts; Organization API (key with `admin:*`) recreates/terminates/deletes computers.
